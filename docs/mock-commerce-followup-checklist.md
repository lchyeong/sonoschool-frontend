# 목데이터 기반 주문/결제 후속 작업 체크리스트

## 목적
- 장바구니, 체크아웃, 결제 결과, 마이페이지 주문/수강 흐름을 목데이터 기준으로 일관되게 정리한다.
- 프론트 화면 기준 DTO를 먼저 고정하고, 이후 실제 API 연결 시 매핑 비용을 줄인다.
- 사용자가 이미 정한 정책을 UI와 DTO에 끝까지 반영한다.

## 현재 반영된 상태
- [x] 프로그램 상세에서 장바구니 담기 동작 연결
- [x] 장바구니 삭제 동작 연결
- [x] 중복 담기 차단 및 안내 메시지 적용
- [x] 장바구니 카드에 상세 링크 연결
- [x] 장바구니 카드에 썸네일 노출
- [x] 체크아웃 목결제 결과 페이지 연결
- [x] 결제 결과 mock fallback 및 상태 표시 연결
- [x] 마이페이지 장바구니 카드 UI를 장바구니 페이지와 유사한 패턴으로 정리
- [x] 마이페이지 신청 내역 카드에 링크/썸네일 연결

## 우선순위 높은 후속 작업

### 1. 주문 요약 DTO 통합
- [ ] `ApplicationSummary`에서 `onlineItems`, `offlineItems` 분리 모델을 통합 주문 기준 구조로 재정의
- [ ] `onlinePayablePrice`, `offlineItemCount`, `hasOnlineCheckout`, `hasOfflineReservation` 같은 분리 필드 정리
- [ ] 장바구니 합계 영역 문구를 `결제 가능 항목/별도 확인 항목` 기준이 아니라 통합 주문 기준으로 수정
- [ ] 마이페이지 장바구니 합계도 같은 기준으로 통일
- [ ] 관련 mock/test 전부 새 DTO 기준으로 갱신

### 2. 내 강의 카드 패턴 통일
- [ ] `EnrollmentSummary.programThumbnailUrl`에 실제 mock 이미지 연결
- [ ] 내 강의 목록을 텍스트 버튼형에서 `썸네일 + 제목 + 상태 + 수강기간` 카드형으로 정리
- [ ] 상세 선택 UX는 유지하되, 카드 UI만 주문/신청 카드와 시각 언어를 맞춤
- [ ] 수강 상태 badge/label 톤을 다른 주문 상태 chip과 같이 정리
- [ ] 관련 테스트 갱신

### 3. 체크아웃 주문 항목 정보 보강
- [ ] 체크아웃 주문 항목에 썸네일 추가
- [ ] 체크아웃 주문 항목에 상세 링크 추가
- [ ] 체크아웃 주문 항목에 강사명/유형 등 최소 메타 추가
- [ ] 장바구니 카드와 체크아웃 카드의 컴포넌트 패턴 재사용 가능성 검토

### 4. mock 경로/이미지 매핑 중앙화
- [ ] `mypage` mock 안에 흩어진 `detailPath` 하드코딩을 중앙 매핑으로 추출
- [ ] 가능하면 프로그램 카탈로그 mock 기준으로 경로를 유도하는 방식 검토
- [ ] 썸네일 이미지 매핑도 공통 seed/helper로 정리
- [ ] 경로 변경 시 마이페이지/장바구니 링크가 깨지지 않도록 테스트 추가

## 중간 우선순위 작업

### 5. 결제 흐름 다듬기
- [ ] `목 결제 진행` 문구를 실제 사용 흐름에 맞는 임시 문구로 조정할지 검토
- [ ] 결제 결과 페이지에 주문 항목 요약 노출 여부 검토
- [ ] 결제 실패/취소 상태에서 재시도 동선 개선

### 6. 주문/환불 화면 일관성 정리
- [ ] 환불 내역도 카드 패턴 재사용 여부 검토
- [ ] 상태 라벨 표현을 `신청 완료/신청 확정/취소됨`, `환불 진행 중/환불 완료/취소 완료` 기준으로 재점검
- [ ] 필터/리스트/상세 레이아웃 간격과 정보 밀도 통일

## 보류 항목
- [ ] 로그인 화면/모달의 샘플 계정 자동 입력 적용 여부는 별도 결정 후 반영

## 작업 원칙
- [ ] 사용자가 이미 결정한 정책과 충돌하는 문구/DTO가 남아 있으면 우선 정리
- [ ] 다른 개발자 작업 범위를 침범할 수 있는 구조 변경은 사용자 확인 후 진행
- [ ] 테스트는 화면 변경과 같이 갱신
- [ ] 목데이터 구조 변경 시 query fallback, page, test를 같이 수정
