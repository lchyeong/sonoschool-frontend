# 관리자 기능점검 테스트 체크리스트

작성일: 2026-04-22  
대상: 소노스쿨 프론트엔드 관리자 콘솔

## 1. 점검 방식

### 검토한 3가지 방법

| 방법                   | 내용                                                                       | 장점                                           | 한계                                               |
| ---------------------- | -------------------------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| 메뉴별 CRUD 점검       | 공지사항, 팝업, Q&A처럼 메뉴별로 등록/수정/상태변경/삭제를 확인            | 빠르게 누락 기능 확인 가능                     | 사용자 화면 반영, 권한, 오류 케이스가 빠질 수 있음 |
| 사용자 플로우 E2E 점검 | 관리자에서 변경한 데이터가 사용자 화면까지 반영되는지 확인                 | 실제 운영 영향 확인 가능                       | 초기 체크리스트 작성에는 시간이 더 걸림            |
| 운영 리스크 기반 점검  | 인증, 권한, 세션, 결제 취소, 삭제 확인, 업로드 실패 등 위험 기능 우선 확인 | 장애/사고 가능성이 큰 기능을 먼저 잡을 수 있음 | 단순 CRUD 목록만 원하는 경우 과해질 수 있음        |

### 선택한 방식

이번 기능점검은 `메뉴별 CRUD + 사용자 화면 반영 + 운영 리스크`를 합친 방식으로 진행한다.  
이유는 관리자 기능이 사용자 공개 화면, 결제, 수강권, 실습 예약에 직접 영향을 주기 때문이다.

### 공통 합격 기준

- 관리자 로그인이 안 된 상태에서 `/admin/*` 접근 시 `/admin/login`으로 이동한다.
- 로그인 성공 후 관리자 메뉴가 정상 노출되고, 새로고침 후에도 세션이 유지된다.
- 로그아웃 후 관리자 페이지에 다시 접근하면 로그인 화면으로 이동한다.
- 필수값 누락, 잘못된 날짜 범위, 잘못된 파일 형식에서 명확한 오류가 표시된다.
- 저장/수정/삭제/취소/게시/중지 후 목록, 상세, 요약 숫자, 사용자 화면이 함께 갱신된다.
- 삭제/취소/숨김/결제취소 같은 파괴적 액션은 확인 절차와 결과 메시지가 있다.
- 로딩, 빈 목록, API 오류 상태에서 화면이 깨지지 않는다.
- 긴 제목, 긴 본문, 긴 파일명, 큰 금액, 많은 항목에서 레이아웃이 깨지지 않는다.
- 테스트는 가능한 한 독립적으로 실행하고, 이전 테스트 데이터에 의존하지 않는다.

## 2. 우선 점검 순서

| 순서 | 영역                   | 경로                       | 우선도 | 이유                                     |
| ---- | ---------------------- | -------------------------- | ------ | ---------------------------------------- |
| 1    | 관리자 인증/권한       | `/admin/login`, `/admin/*` | P0     | 모든 관리자 기능의 진입 조건             |
| 2    | 프로그램 관리          | `/admin/programs`          | P0     | 상품, 수강, 결제, 커리큘럼의 기준 데이터 |
| 3    | 결제 관리              | `/admin/payments`          | P0     | 결제 취소와 수강 상태 변경 영향          |
| 4    | 일정관리               | `/admin/practicum`         | P0     | 실습 예약, 출석, 운영시간 영향           |
| 5    | 공지사항 관리          | `/admin/notices`           | P1     | 사용자 공개 콘텐츠                       |
| 6    | 팝업 관리              | `/admin/popups`            | P1     | 홈 화면 노출 영향                        |
| 7    | Q&A 관리               | `/admin/qna`               | P1     | 고객 응대 상태 영향                      |
| 8    | 자료실 관리            | `/admin/resources`         | P1     | 파일 다운로드/공개 자료 영향             |
| 9    | 회원관리               | `/admin/enrollments`       | P1     | 회원 상세, 결제, 수강, 학습 이력 확인    |
| 10   | 프로그램 카테고리 관리 | `/admin/program-menus`     | P1     | 헤더/과정 탐색 구조 영향                 |
| 11   | 교육후기 관리          | `/admin/reviews`           | P2     | 현재 지연 섹션으로 표시됨                |

## 3. 기능별 점검 목록

### 3.1 관리자 인증/권한

| 체크 | 점검 항목                                    | 기대 결과                                               |
| ---- | -------------------------------------------- | ------------------------------------------------------- |
| [ ]  | 관리자 아이디/비밀번호 필수값 검증           | 비어 있는 입력값에 오류가 표시되고 포커스가 이동한다    |
| [ ]  | 정상 로그인                                  | `/admin/programs`로 이동하고 관리자 이름이 표시된다     |
| [ ]  | 잘못된 계정 로그인                           | 로그인 실패 토스트가 표시되고 로그인 상태가 되지 않는다 |
| [ ]  | 미로그인 상태에서 `/admin/notices` 직접 접근 | `/admin/login`으로 이동한다                             |
| [ ]  | 로그인 후 `/admin/login` 접근                | 관리자 기본 화면으로 이동한다                           |
| [ ]  | 로그아웃                                     | 세션 종료 토스트 후 관리자 접근이 차단된다              |
| [ ]  | 세션 만료 상태                               | 자동 로그아웃되고 로그인 화면으로 이동한다              |

### 3.2 공지사항 관리

| 체크 | 점검 항목             | 기대 결과                                                                      |
| ---- | --------------------- | ------------------------------------------------------------------------------ |
| [ ]  | 공지 목록 조회        | 전체 전역 공지, 게시 중, 고정 공지 수가 표시된다                               |
| [ ]  | 새 공지 등록          | `/admin/notices/new`에서 등록 후 목록에 추가된다                               |
| [ ]  | 제목/본문 필수값 검증 | 필수값 누락 시 저장되지 않고 오류가 표시된다                                   |
| [ ]  | 리치 텍스트 본문 입력 | 굵게, 링크, 줄바꿈, 표/이미지 등 입력 결과가 저장된다                          |
| [ ]  | 공지 수정             | `/admin/notices/:noticeId/edit`에서 수정 후 목록의 제목/요약/수정일이 갱신된다 |
| [ ]  | 고정 공지 설정/해제   | 고정 여부가 목록과 사용자 공지 목록 정렬에 반영된다                            |
| [ ]  | 게시 처리             | 비공개 공지가 게시 중으로 변경되고 `/notices`에 노출된다                       |
| [ ]  | 중지 처리             | 게시 중 공지가 비공개로 변경되고 `/notices`와 상세에서 노출되지 않는다         |
| [ ]  | 삭제 취소             | 삭제 확인창에서 취소하면 데이터가 유지된다                                     |
| [ ]  | 삭제 확인             | 삭제 후 관리자 목록과 사용자 목록에서 사라진다                                 |
| [ ]  | 긴 제목/긴 본문       | 관리자 목록, 사용자 목록, 상세 화면에서 레이아웃이 깨지지 않는다               |

### 3.3 팝업 관리

| 체크 | 점검 항목                | 기대 결과                                                    |
| ---- | ------------------------ | ------------------------------------------------------------ |
| [ ]  | 팝업 목록 조회           | 전체 팝업, 게시 중, 현재 노출 대상 요약이 표시된다           |
| [ ]  | 이미지 업로드            | 이미지 미리보기가 표시되고 이미지 설명 기본값이 생성된다     |
| [ ]  | 이미지 없는 등록 방지    | 이미지가 없으면 등록되지 않고 오류가 표시된다                |
| [ ]  | 이미지 설명 필수값 검증  | 설명이 비어 있으면 등록되지 않는다                           |
| [ ]  | 정렬 순서 검증           | 0 미만 값은 저장되지 않는다                                  |
| [ ]  | 노출 시작/종료 검증      | 시작일이 종료일보다 늦으면 저장되지 않는다                   |
| [ ]  | 새 팝업 등록             | 등록 후 목록과 선택한 팝업 영역에 반영된다                   |
| [ ]  | 등록과 동시에 게시 옵션  | 체크 여부에 따라 게시/비공개 상태가 저장된다                 |
| [ ]  | 팝업 수정                | 이미지 설명, 정렬, 노출 기간이 수정된다                      |
| [ ]  | 게시/중지                | 홈 팝업 노출 대상이 상태와 기간에 맞게 바뀐다                |
| [ ]  | 현재 노출 우선순위       | 게시 상태, 노출 기간, 정렬 순서 기준으로 1개만 홈에 노출된다 |
| [ ]  | 이미지 제거 후 저장 시도 | 이미지 필수 오류가 표시된다                                  |
| [ ]  | 삭제                     | 삭제 후 목록과 홈 팝업에서 제거된다                          |

| [ ]  | 새로고침            | 저장된 데이터는 유지되고 작성 중 미저장 데이터는 정책대로 처리된다 |

## 6. 자동화 후보

### 바로 E2E 자동화할 항목

- 관리자 로그인/로그아웃/권한 차단
- 공지사항 등록, 수정, 게시, 중지, 삭제
- 자료실 등록, 수정, 삭제, 사용자 화면 반영
- Q&A 답변 등록, 삭제
- 프로그램 목록 검색/필터/공개/숨김
- 결제 상세 조회와 취소 사유 필수값 검증

### 수동 점검을 유지할 항목

- 실제 KCP 취소 성공 여부
- 실제 S3 업로드/인코딩/대용량 파일 업로드
- 운영시간 변경과 기존 예약 충돌 정책
- 화면 깨짐, 긴 텍스트, 이미지 품질 확인

## 7. 개선안과 반영 결정

| 자동화 후보와 수동 점검 후보를 분리              | 테스트 비용과 신뢰성 균형 확보           | 반영                |
