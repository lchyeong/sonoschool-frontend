# SONO SCHOOL UI/UX 기능 및 사용자 플로우 점검 문서

작성 기준: 프론트엔드 코드 기준 라우트, 화면, CTA, 상태 분기 확인  
대상 저장소: `sonoschool-frontend`  
주요 참고 파일: `src/routes/routeRegistry.ts`, `src/routes/router.tsx`, `src/pages/**`, `src/components/**`

## 1. 문서 목적

이 문서는 UI/UX 디자이너가 SONO SCHOOL 프론트 화면을 검토할 때 필요한 기능 범위와 사용자 흐름을 빠르게 이해하기 위한 자료입니다.

검토 시에는 단순 화면 미감보다 아래 항목을 우선 확인합니다.

- 사용자가 다음 행동을 명확히 알 수 있는지
- 로그인 전/후, 빈 상태, 로딩, 오류, 마감, 완료 같은 상태가 자연스럽게 이어지는지
- 데스크톱과 모바일에서 같은 업무를 문제없이 완료할 수 있는지
- 교육과정 탐색, 장바구니, 결제, 수강, Q&A, 실습 예약 흐름이 끊기지 않는지
- 관리자에서 입력한 콘텐츠가 사용자 화면에 무리 없이 표시되는지

## 3. 공통 레이아웃 및 네비게이션

### 헤더

- 데스크톱: 로고, 1차 메뉴, 하위 메뉴 드롭다운, 장바구니 아이콘, 로그인 또는 계정 메뉴
- 모바일: 로고, 장바구니 아이콘, 햄버거 메뉴, 모바일 드로어
- 스크롤 시 헤더 자동 숨김 처리
- KCP 결제창 노출 중에는 헤더가 결제 UI를 방해하지 않도록 숨김 처리
- 장바구니 배지는 항목 수를 표시하며 99개 초과 시 `99+`

### 푸터

- 학습 플레이어 같은 전체 화면 학습 라우트에서는 헤더/푸터를 숨김
- 일반 공개 페이지에는 공통 푸터 노출

### 접근 제어

- 공개: 홈, 검색, 과정, 공지, Q&A, 자료실, 장바구니, 결제 결과
- 로그인 전용: 마이페이지, 결제 페이지, 학습 플레이어, 수강 실습 예약
- 게스트 전용: 로그인, 회원가입, 계정 찾기
- 관리자 전용: 관리자 콘솔 전체

점검 포인트:

- 로그인 전용 경로 진입 시 로그인 페이지로 이동하고, 로그인 후 원래 가려던 경로로 복귀하는지
- 로그인 상태에서 로그인/회원가입 페이지 접근 시 마이페이지로 이동하는지
- 관리자 세션 만료 시 관리자 로그인으로 이동하는지
- 모바일 메뉴 열림 상태에서 배경 스크롤이 잠기는지
- 드롭다운, 모바일 메뉴, 계정 메뉴가 Escape와 바깥 클릭에서 닫히는지

## 4. 핵심 사용자 플로우

### A. 비로그인 탐색에서 수강 신청까지

1. 홈 진입
2. 검색 또는 헤더 메뉴로 교육과정 탐색
3. 교육과정 허브 또는 과정군 페이지에서 대표 과정 확인
4. 과정 상세 진입
5. 강의 소개, 커리큘럼, 수강평, FAQ, Q&A 확인
6. `장바구니` 또는 `수강 신청 하기` 선택
7. 장바구니는 비로그인 상태에서도 담을 수 있음
8. 결제 단계 진입 시 로그인이 필요하면 로그인으로 이동
9. 로그인 성공 후 장바구니가 서버 장바구니로 병합됨
10. 결제 진행 후 결제 결과 확인
11. 결제 완료 시 마이페이지 내 강의로 이동

디자인 점검 포인트:

- 상세 페이지 우측 가격/CTA 영역이 스크롤 중에도 행동을 유도하는지
- 모바일 하단 고정 CTA가 상세 본문을 가리지 않는지
- 비로그인 장바구니와 로그인 후 장바구니 병합 상태를 사용자가 이해할 수 있는지
- 결제 전 선택 항목 없음, 장바구니 비어 있음, 결제 실패/취소 상태의 복귀 동선이 명확한지

### B. 정원 마감 또는 모집 상태별 신청 흐름

과정 카드는 모집 상태에 따라 CTA가 달라집니다.

- 신청 가능: 장바구니 아이콘 또는 수강 신청
- 정원 마감: 로그인 전에는 `로그인 후 알림 받기`, 로그인 후에는 `알림 받기`
- 알림 신청 완료: `알림 신청 완료` 비활성 상태
- 모집 예정: `모집 예정` 비활성 상태
- 운영 중/모집 종료: `신청 마감` 비활성 상태

디자인 점검 포인트:

- `신청 가능`, `정원 마감`, `모집 예정`, `신청 마감`의 시각적 위계가 구분되는지
- 정원 마감 알림 신청이 장바구니/결제 CTA와 혼동되지 않는지
- 목록 카드와 상세 사이드바의 상태 표현이 일관적인지

### C. 로그인 및 회원가입

로그인:

- 아이디/비밀번호 입력
- 새 환경 로그인으로 판단되면 SMS 인증 단계 노출
- 개발 환경 인증번호는 `123456`으로 고정
- 로그인 성공 시 비로그인 장바구니를 서버 장바구니로 병합
- 로그인 후 원래 접근하려던 경로 또는 마이페이지로 이동

회원가입:

- 아이디 중복확인
- 이메일 입력 시 이메일 중복확인
- 이름, 닉네임, 비밀번호, 비밀번호 확인
- 휴대폰 번호 입력, 인증번호 발송, 인증번호 확인, 남은 시간 표시
- 약관 전체 동의/개별 동의
- 가입 성공 시 자동 로그인 후 마이페이지 이동

디자인 점검 포인트:

- 중복확인, 인증번호 발송, 인증번호 확인이 각각 별도 단계로 이해되는지
- SMS 남은 시간, 만료, 인증 완료 상태가 명확한지
- 입력 오류가 필드 근처에서 바로 해석되는지
- 모바일에서 중복확인 버튼과 입력 필드가 과밀하지 않은지

### D. 장바구니와 결제

장바구니:

- 담은 강의 목록
- 전체 선택/개별 선택
- 강의 삭제
- 선택 상품 수, 상품 금액, 강의 할인, 총 결제 금액
- 선택 항목이 없으면 결제 버튼 비활성 및 안내 노출

결제:

- 주문자 정보 확인
- 선택한 주문 항목 확인
- 최종 결제 금액 확인
- 무료 신청이면 `무료 신청`
- 유료 결제면 KCP 결제
- PC 결제는 결제창 준비 상태, 결제창 닫힘/취소/승인 실패 처리
- 모바일 결제는 모바일 KCP 등록 후 외부 결제 페이지로 제출

결제 결과:

- 결제 완료: 결제 정보, 내 강의 이동, 홈 이동, 영수증 보기
- 결제 실패: 실패 안내, 홈 이동
- 결제 취소/대기: 결제 다시 시도, 장바구니로 돌아가기

디자인 점검 포인트:

- 장바구니 선택 상태와 결제 페이지 선택 항목이 서로 연결되어 보이는지
- 결제창 준비 중/여는 중 상태에서 중복 클릭을 막는 상태가 충분히 보이는지
- 실패와 취소 문구가 사용자 책임처럼 보이지 않는지
- 결제 완료 후 다음 행동이 `내 강의로 이동` 중심으로 잡히는지

### E. 마이페이지

마이페이지는 사이드 메뉴로 4개 탭을 전환합니다.

- 내 강의
- 결제내역
- 내정보관리
- Q&A관리

내 강의:

- 수강 중, 수강 종료, 수료증 탭
- 진행률, 완료 강의 수, 수강 기간, 최근 학습 표시
- 수강 중 강의는 `이어보기`
- 수료증 대상은 `수료증 다운로드`
- 후기 작성/수정 가능

결제내역:

- 전체/결제 완료/결제 취소 필터
- 주문명, 주문번호, 결제수단, 결제일, 금액, 상태
- 결제 상세 모달

내정보관리:

- 아이디, 이메일 읽기 전용
- 이름, 닉네임 수정
- 휴대폰 인증 상태 표시
- 휴대폰 번호 변경: 새 번호 입력, 인증번호 받기, 인증번호 입력, 번호 변경
- 로그아웃

Q&A관리:

- 운영 Q&A와 강의 Q&A 통합 확인
- 전체/운영 Q&A/강의 Q&A 필터
- 전체/답변 완료/답변 대기 필터
- 키워드 검색
- 답변 펼침/닫힘

디자인 점검 포인트:

- 사이드 메뉴가 모바일에서 과도하게 좁아지지 않는지
- 내 강의 카드의 `이어보기`, `후기 작성`, `수료증 다운로드` 행동이 구분되는지
- 결제 상세 모달이 영수증처럼 읽히는지
- Q&A 필터 2줄과 검색이 복잡해 보이지 않는지

### F. 학습 플레이어

학습 플레이어는 콘텐츠 유형에 따라 중앙 작업 영역이 달라집니다.

공통:

- 상단: 내 강의로 돌아가기, 진도율, 운영기간
- 우측 패널: 강의 목록 또는 Q&A 전환
- 강의 목록: 섹션별 접힘, 강의 유형 배지, 완료 상태, 현재 강의 강조
- 진도 저장: 재생 중 주기 저장, 종료/이탈 시 저장

영상 강의:

- 보호된 HLS 스트리밍
- 재생 속도: 0.8x, 1x, 1.25x, 1.5x
- 해상도: 자동 및 수동 옵션
- 스트리밍 준비 중, 브라우저 미지원, 재생 오류 표시

오프라인 강의:

- 영상 대신 오프라인 일정 달력 표시
- 등록된 날짜와 시간 확인
- 일정 미등록 상태 표시

자료 강의:

- 첨부파일 목록
- 파일 타입, 파일명, 용량
- 다운로드 버튼
- 첨부파일 없음 상태

문제풀이 강의:

- 문제 정보 로딩/오류/없음 상태
- 문제 문항, 단일/복수 선택
- 문항 미디어, 보기 미디어
- `나중에 풀기`
- 이전/다음, 제출
- 제한시간
- 우측 문제 네비게이터: 미입력, 답변 완료, 나중에 풀기
- 채점 결과: 점수, 통과/재도전, 정답/오답, 선택 답안, 정답, 해설
- 풀이 상태 자동 저장

실습 예약 강의:

- 실습 예약 달력
- 날짜별 예약 가능 수, 예약 예정/완료/불참 상태
- 선택 날짜의 시간 슬롯
- 예약, 예약 취소, 일정 변경
- 예약 불가 사유 표시

강의 Q&A:

- 플레이어 우측 패널에서 강의 Q&A 전환
- 로그인 상태에서는 질문/답글 작성 가능
- 작성자 유형: 관리자, 수강생, 회원
- 답변 완료/미해결 상태

디자인 점검 포인트:

- 영상이 없는 콘텐츠도 “오류”처럼 보이지 않고 학습 콘텐츠로 보이는지
- 플레이어의 우측 목록/Q&A 전환이 눈에 잘 들어오는지
- 문제풀이의 문항 네비게이터가 긴 문제 수에서도 사용 가능한지
- 실습 예약 달력에서 `예약 가능`, `예약됨`, `불참`, `완료`, `예약 불가`가 구분되는지
- 모바일에서 플레이어, 목록, Q&A, 문제 네비게이터가 한 화면에 과밀하지 않은지

### G. 운영 Q&A와 강의 Q&A

운영 Q&A:

- 공개 게시판 형태
- 답변 상태 필터: 전체, 답변완료, 답변대기
- 제목/내용/작성자 검색
- 공지 행 노출
- 질문 클릭 시 질문 내용과 답변 펼침
- 로그인 후 글쓰기 가능

강의 Q&A:

- 과정 상세 탭 또는 플레이어 패널에서 사용
- 게시판형/컴팩트형/패널형 레이아웃 존재
- 답변 상태 필터와 검색
- 질문 작성, 답글 작성
- 작성자 이름 마스킹
- 관리자 답변 배지

디자인 점검 포인트:

- 운영 Q&A와 강의 Q&A가 비슷하지만 맥락이 다름을 사용자가 이해할 수 있는지
- 답변 상태, 작성자 유형, 답글 수가 표/카드 양쪽에서 일관적인지
- 글쓰기 폼이 열렸을 때 목록과 혼동되지 않는지

### H. 공지사항과 자료실

공지사항:

- 검색
- 필독 배지
- HTML 본문 상세
- 목록 복귀

자료실:

- 검색
- 공개/과정 구분 배지
- 첨부 개수
- 상세 진입
- 다운로드 전 확인창
- 다운로드 성공/실패 토스트

디자인 점검 포인트:

- 게시판 테이블이 모바일에서 읽기 쉬운지
- 공지 상세의 리치 텍스트 스타일이 관리자 입력 결과를 안정적으로 담는지
- 자료 첨부 카드가 파일 타입과 실제 파일명을 명확히 보여주는지

### I. 홈

홈 구성:

- 상단 통합 검색
- 메인 슬라이드 캐러셀
- 기능 소개
- 히스토리 타임라인
- 공지 섹션
- 홈 진입 시 활성 팝업 모달

팝업:

- 이미지 기반 모달
- `오늘은 닫기`
- `닫기`
- 오늘은 닫기는 로컬 스토리지에 날짜 저장

디자인 점검 포인트:

- 검색이 첫 화면에서 충분히 주요 행동으로 보이는지
- 슬라이드 로딩/오류 상태가 비어 보이지 않는지
- 팝업이 홈 CTA와 충돌하지 않는지

## 5. 관리자 기능 요약

관리자 콘솔은 사용자 화면에 노출되는 콘텐츠와 운영 상태를 관리합니다.

- 공지사항 관리: 공지 목록, 필독 여부, 작성/수정
- 팝업 관리: 홈 팝업 이미지와 노출 상태
- Q&A 관리: 운영/강의 문의 답변
- 자료실 관리: 공개 자료와 첨부 관리
- 회원관리: 회원 검색, 회원별 상세, 수강 상태 확인
- 일정관리: 운영시간, 당일 운영 변경, 개인일정, 실습 예약, 오프라인 강의 일정, 출석/불참 관리
- 프로그램 관리: 프로그램 목록, 초안, 신규 작성, 수정, 복제, 삭제, 공개/숨김/초안 상태
- 프로그램 카테고리 관리: 헤더와 교육과정 메뉴 구조
- 결제 관리: 결제 목록, 결제 상세, 매출 그래프, 취소 처리

관리자 UI 점검 포인트:

- 관리자 입력 결과가 사용자 화면의 카드, 상세, 팝업, 게시판에 어떻게 반영되는지 추적 가능한지
- 프로그램 작성 플로우가 기본 정보, 커리큘럼, 문제, 자료를 잃지 않고 이어지는지
- 일정관리 달력에서 실습, 오프라인 강의, 개인일정, 운영시간 변경이 서로 구분되는지
- 결제 취소 같은 위험 행동은 충분히 확인 가능한지

## 8. 디자이너에게 전달할 핵심 질문

- 주요 CTA가 화면마다 하나의 다음 행동으로 명확히 보이는가?
- 교육과정 카드와 상세 페이지에서 가격, 모집 상태, 잔여석, 일정 정보의 우선순위가 적절한가?
- 과정 상세의 정보량이 많을 때 탭, 사이드바, 모바일 하단 CTA가 사용자를 돕는가?
- 플레이어에서 콘텐츠 유형이 바뀌어도 같은 학습 공간이라는 일관성이 유지되는가?
- 게시판형 UI가 데스크톱 표와 모바일 카드 모두에서 읽기 쉬운가?
- 관리자에서 입력한 긴 제목, 긴 본문, 많은 첨부, 많은 회차가 사용자 화면에서 깨지지 않는가?
- 실패/마감/빈 상태 문구가 사용자를 막는 대신 다음 행동을 안내하는가?

## 9. 특히 놓치면 안 되는 UX 리스크

- 모바일 과정 상세 하단 CTA가 본문 또는 푸터와 겹칠 수 있음
- 게시판 테이블은 모바일 폭에서 컬럼 축약 전략이 필요함
- 학습 플레이어는 기능이 많아 모바일에서 우측 패널, 문제 네비게이터, Q&A 전환 구조가 복잡해질 수 있음
- 결제창 노출 중 헤더/스크롤 잠금이 결제 UI를 방해하지 않아야 함
- 회원가입 SMS 인증은 시간, 재발송, 인증 완료 상태가 혼동되기 쉬움
- 실습 예약 달력은 예약 가능, 예약됨, 완료, 불참, 예약 불가를 색상만으로 구분하면 접근성이 약해질 수 있음
- 관리자 리치 텍스트/첨부/이미지 입력 결과가 사용자 화면에서 예측 가능해야 함
